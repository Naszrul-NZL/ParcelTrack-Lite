# ParcelTrack Airway

Read the repository's [DESIGN.md](../../../DESIGN.md) for the approved visual direction and [design contribution guide](../../../docs/design/CONTRIBUTING.md) for ownership and feature boundaries. Exact shared values live in [airway.tokens.json](../../../docs/design/airway.tokens.json). The runnable [Airway reference](../../../docs/design/airway-reference.html) shows the intended hierarchy, docket and theme treatment.

Use the repository-local copies of [antislop](../antislop/SKILL.md), [antislop-ui](../antislop-ui/SKILL.md) and the task-relevant [accessibility](../antislop-human/SKILL.md) or [responsive](../antislop-layoutmobile/SKILL.md) supplement. The repository's explicit default is antislop during; its installation is already complete. Do not rerun the installer wizard or write global preferences. A user's current task instructions take precedence.

Airway's identity comes from Barlow Condensed status typography, DM Sans controls, indigo actions, a lavender parcel docket and yellow current-stage markers. Preserve these roles when a generic search suggests other visual defaults. Use [ui-ux-pro-max](../ui-ux-pro-max/SKILL.md) for targeted interaction/component research when needed; do not regenerate the approved design system for routine module work.

Implement through the project's existing shared shadcn/Base UI components. Give recipients a clear current status; give staff efficient role-specific records and actions. Keep normal form and record text comfortably readable and the docket specific to parcel documents.

Apply recommended additions when implementing the relevant module. A mockup does not authorize a new backend feature: public tracking is limited by its DTO, tracking sharing needs a reviewed contract, and proof remains private. The actual workflow includes FAILED as an alternate outcome; do not force every record into a delivered-only path.

Check affected layouts, themes and state transitions in the browser, including phone reflow and keyboard use. Run the relevant existing checks and record what actually passed. Keep concurrent work and unrelated modules outside the change. Update shared tokens and the guide together when a cross-module design choice is intentionally revised.
